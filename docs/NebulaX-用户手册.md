## 1. 产品简介

NebulaX 是一款面向运维工程师与开发者的桌面终端管理工具，核心能力：

- **多协议终端**：SSH、Telnet、串口、本地终端，以及 RDP/VNC 外部会话启动
- **AI 深度集成**：终端内嵌 AI 助手、命令智能补全、安全审计、故障诊断、容量预测、脚本生成
- **文件传输**：SFTP 双栏管理、断点续传、并发传输队列
- **批量运维**：多标签、分屏、同步输入、宏录制回放
- **网络能力**：SSH 隧道（本地端口转发 + SOCKS5 动态代理）、跳板机、HTTP/SOCKS5 代理
- **主动运维**：定时巡检、超阈值系统通知预警
- **安全加固**：主机指纹校验（TOFU）、系统凭据库加密存储、命令注入防护

支持多家 AI 服务商（DeepSeek / OpenAI / Anthropic / 智谱 / Moonshot / 通义千问 / **Ollama 本地模型** / 任意 OpenAI 兼容接口）。

## 2. 安装与启动

### 安装（Windows）

1. 双击 `NebulaX-Setup-1.4.0.exe`
2. 安装向导中选择安装目录（默认 `C:\Program Files\NebulaX`）
3. 勾选创建桌面快捷方式
4. 完成安装后从桌面图标或开始菜单启动

### 系统要求

- Windows 10/11（64 位）
- 无需预装 Node.js 或 Python，应用已内置全部运行时

### 首次启动

首次启动会创建用户数据目录 `~/.nebula-ssh/`（见 [14. 数据文件位置](#14-数据文件位置)），不需要任何初始化配置。

### 许可与激活

NebulaX 采用**离线激活**模式，激活过程不需要联网：

- **试用**：首次启动即进入 14 天全功能试用，顶栏显示「试用 N 天」徽章。
- **激活**：顶栏点击许可徽章（钥匙图标）打开「许可激活」窗口，把窗口中的**机器码**提供给厂商，换取与本机绑定的激活码后粘贴激活。激活码支持**永久买断**与**年度订阅**两种类型。
- **到期**：试用或订阅到期后进入只读模式——可查看已保存的主机与历史数据，新建连接、终端会话与 AI 功能锁定；输入激活码立即恢复。
- **换机**：在旧电脑的许可窗口点击「注销激活」，再到新电脑输入同一激活码即可（机器码随硬件变化，需重新换取新码也可行）。
- 机器码由主机名、网卡与用户名指纹生成，不上传任何数据；激活验证全程在本机完成。

## 4. 连接管理

### 4.1 新建 SSH 连接

1. 点击顶栏「新建连接」或侧边栏「+」
2. 协议选择 **SSH**，填写：
   - **名称**：便于识别的别名（如"生产-web-01"）
   - **主机 / 端口**：默认端口 22
   - **认证方式**：密码 或 私钥（可填私钥路径）
3. 可选高级配置（展开"高级"）：
   - **跳板机**：先连跳板再连目标，支持跳板用密码或私钥认证
   - **代理**：SOCKS5 / HTTP 代理，支持账号密码认证
4. 点击「测试连接」验证，再「保存并连接」

### 4.2 其他协议

| 协议 | 必填项 | 说明 |
|------|--------|------|
| Telnet | 主机、端口（默认 23） | 网络设备调试常用 |
| 串口 | 串口号（自动枚举）、波特率 | 嵌入式/设备调试，支持实时绘图 |
| 本地终端 | 选择 Shell | Windows：PowerShell / CMD / Git Bash（自动探测已安装工具） |
| RDP | 主机、账号 | 调用系统远程桌面连接（mstsc）外部启动 |
| VNC | 主机、Viewer 路径 | 调用本机 VNC 客户端外部启动 |

### 4.3 主机指纹校验（TOFU）

- 首次连接新主机时，弹窗展示服务器指纹，**确认信任**后才继续连接
- 指纹记录在 known_hosts，后续连接自动比对
- 若指纹发生变化（如服务器重装），会**拒绝连接并明确警告**，需手动在「主机指纹管理」中删除旧记录后重新信任
- 这是防止中间人攻击的关键防线，不要盲目点信任

### 4.4 分组管理

- 侧边栏右键或管理入口可创建分组（如"生产环境"、"测试环境"）
- 连接可拖动/编辑归属分组，分组支持排序
- 大量服务器时按分组折叠显示，快速定位

### 4.5 会话恢复

- 关闭应用时未关闭的标签会被记录
- 下次启动自动恢复为"未连接"状态的标签，**双击即可重连**，无需重新配置

## 5. 终端使用

### 5.1 多标签与分屏

- 顶栏下方标签页切换会话，右键可重命名/关闭
- 支持**横向/纵向分屏**（最多 4 窗格），每个窗格独立会话
- 视图切换按钮可在「终端」「文件（SFTP）」之间切换

### 5.2 命令智能补全

- 输入命令时自动弹出补全候选：本地命令/路径补全 + **AI 联想补全**
- AI 候选置顶并附带一句话参数解释（✨ 标记）
- `Ctrl+Space` 手动触发；`↑/↓` 选择，`Tab`/`Enter` 上屏，`Esc` 关闭
- 补全按"输入行+待补全词"缓存，重复触发零成本

### 5.3 终端搜索

- `Ctrl+F` 或点击「搜索」唤起搜索条
- 支持**正则表达式**、**大小写敏感**开关
- 增量搜索，实时显示匹配数，`Enter`/`Shift+Enter` 跳转上/下一个

### 5.4 同步输入（批量操作）

- 顶栏无线电图标开启后，**按键广播到所有已连接的终端**
- 适合批量在多台服务器执行相同命令
- ⚠️ 开启时图标闪烁提醒，操作完成后务必关闭，避免误输入

### 5.5 宏 / 快捷指令

- 终端顶栏「宏」打开面板
- **录制**：点「开始录制」→ 在终端操作 → 停止并命名保存（如"重启 nginx"）
- **回放**：一键把录制的按键序列写入当前会话（逐键 30ms，避免丢键）
- 宏也可当作快捷指令：存一条 `htop⏎` 就是一键启动 htop

### 5.6 复制 / 粘贴

- `Ctrl+Shift+C` 复制、`Ctrl+Shift+X` 剪切、`Ctrl+V` 粘贴
- `Ctrl+C`：**有选区时复制，无选区保持中断（SIGINT）语义**
- 右键菜单提供同样的编辑操作

### 5.7 断线自动重连

- 网络闪断后自动重连，顶栏显示"重连中（第 n/m 次）"
- 心跳探活：长时间无响应主动检测并触发重连
- 重连成功后终端会话自动恢复

### 5.8 串口实时绘图（串口会话专属）

- 串口会话顶栏出现「绘图」按钮
- 自动解析输出行中的数值（支持负数、小数），实时绘制曲线
- 最多 8 通道，统一 Y 轴缩放，用于观察传感器数据趋势

## 6. AI 能力

### 6.1 配置 AI 服务商

顶栏「设置」→「AI 助手配置」：

1. 选择服务商（预置 DeepSeek / OpenAI / Anthropic / 智谱 / Moonshot / 通义千问 / **Ollama 本地** / 自定义）
2. 填入 **API Key**（Ollama 本地模型**无需 Key**）
3. 可调整 **模型名称**、**温度**（0=精确，1=创意）、**最大 Token 数**
4. 点「测试连接」验证后「保存配置」

**关于 Ollama 本地模型（v1.4 新增）**：

1. 本机安装 [Ollama](https://ollama.com) 并启动
2. `ollama pull qwen2.5:7b`（或任一模型）
3. NebulaX 中选择「Ollama 本地」，Base URL 默认 `http://127.0.0.1:11434/v1`，填入模型名即可
4. 数据不出本机，适合对数据合规要求高的场景

API Key 由**系统安全存储（Credential Vault）加密保存**，不会明文落盘。

### 6.2 Token 用量统计（v1.4 新增）

- 设置弹窗底部展示：今日 Tokens / 输入 / 输出 / 调用次数
- 按模型汇总近 90 天用量，便于估算成本
- 记录文件：`~/.nebula-ssh/token-usage.json`（权限 600，仅本用户可读）

### 6.3 终端内嵌 AI 运维助手（v1.4 新增）

终端顶栏「AI 助手」打开侧边抽屉：

- **上下文感知**：自动携带终端当前屏幕输出；**先在终端选中文本再提问**，AI 会优先分析选中内容
- **快捷动作**：解释最近的报错 / 解释当前屏幕 / 下一步怎么做
- **多轮对话**：连续追问，保持上下文
- **命令一键落地**：回复中的 shell 命令显示为「插入」按钮，点击写入终端输入行（**不自动回车**，人工确认后执行，防误操作）
- AI 未配置或请求失败时给出明确提示

### 6.4 其他 AI 功能

| 功能 | 入口 | 说明 |
|------|------|------|
| 安全审计 | AI 面板 | 采集 SSH 配置/SUID/端口等，**本地规则引擎先判定**（白名单防误报、证据逐字校验、确定性评分），AI 补充语义类风险并输出加固建议；检查项覆盖透明可查（通过/风险/跳过） |
| 故障诊断 | AI 面板 | AI 先生成排查步骤，逐条执行后汇总诊断报告 |
| 容量预测 | AI 面板 | 基于指标趋势线性预测磁盘/内存"还有几天写满" |
| 脚本生成 | AI 面板 | 自然语言描述需求 → 生成运维脚本 |
| Runbook 知识库 | AI 面板 | 导入运维文档，AI 回答时检索相关段落作为上下文 |

## 7. SFTP 文件管理

标签页区域切换到「文件」视图：

- **双栏布局**：左侧本地目录、右侧远程目录
- 上传/下载：拖拽或按钮，支持**断点续传**（网络中断后重传从断点继续）
- **传输队列**：并发上限 2（避免多路复用互相饿死带宽），进行中任务可**取消**
- 传输进度、速度、百分比实时显示；失败任务保留在列表可重试/移除
- 远程操作：新建目录、重命名、删除；本地操作同样支持
- 首次进入自动定位用户主目录

## 8. SSH 隧道

仅 SSH 会话可用，顶栏路由图标打开：

- **本地转发（Local Forward）**：把远程服务器上的端口映射到本地
  - 例：访问数据库内网实例 `本地 15432 → 内网DB:5432`
- **动态 SOCKS5 代理**：把 SSH 变成 SOCKS5 代理，浏览器/工具挂代理访问内网
  - 例：`本地 1080 → SOCKS5`，浏览器设置代理 `127.0.0.1:1080`
- 隧道列表实时显示运行状态，可一键停止
- 会话断开时隧道自动清理

## 9. 数据库快速查询

仅 SSH 会话可用，顶栏数据库图标打开（无需在本地装 mysql/psql 客户端）：

1. 选择数据库类型（MySQL / PostgreSQL），填写主机（默认 localhost）、端口、库名、账号、密码
2. 「测试连接」→ 「保存配置」
3. SQL 输入区 `Ctrl+Enter` 执行
4. 结果以表格展示（NULL 斜体显示，超过 500 行自动截断并提示）

安全设计：

- 密码通过**环境变量**（MYSQL_PWD / PGPASSWORD）传给远端 CLI，**不出现在命令行参数**（避免 ps 泄露）
- 所有输入经 shell 转义，防命令注入
- 查询经 SSH 在**远端服务器执行**，数据库无需对外暴露

## 10. 定时巡检与预警（v1.4 新增）

顶栏盾牌警示图标打开：

1. **开启自动巡检**，设置间隔（5~1440 分钟，默认 30 分钟）
2. 设置阈值：CPU（默认 85%）、内存（默认 90%）、磁盘（默认 90%）
3. 可开关「严重告警发系统通知」
4. 「保存并生效」后，按间隔对**所有已连接 SSH 会话**自动采集指标
5. 也可「立即巡检」手动跑一轮

结果面板显示每台主机的 CPU/内存/磁盘明细；超阈值项标注：

- 🟡 警告：超过阈值
- 🔴 严重：≥95%（磁盘即将写满等紧急情况）
- 每条告警附**排查建议与现成命令**（可直接复制执行）
- 🔴 严重告警触发 **Windows 系统通知**，不盯屏幕也能收到

巡检计划持久化保存，**应用重启后自动恢复**。

## 11. 安全与凭据

- **凭据保管库**：密码/私钥经操作系统安全存储（Windows DPAPI）加密，不落明文盘
- **主机指纹 TOFU**：详见 4.3
- **数据库密码**：环境变量传递，不进进程参数列表
- **本地文件安全边界**：SFTP 本地栏限制在用户主目录内，禁止访问系统目录
- **命令确认**：AI 生成的命令一律"先插入、人工回车"，绝不自动执行

## 14. 数据文件位置

所有用户数据位于 `~/.nebula-ssh/`（Windows 为 `C:\Users\<用户名>\.nebula-ssh\`）：

| 文件/目录 | 内容 |
|-----------|------|
| `connections.json` | 保存的连接配置（不含明文密码） |
| `ai-config.json` | AI 服务商配置 |
| `token-usage.json` | Token 用量统计（权限 600） |
| `patrol-config.json` | 巡检计划与阈值 |
| `known_hosts` | 已信任的主机指纹 |
| `macros.json` | 宏/快捷指令 |
| `runbooks/` | Runbook 知识库文档 |
| `logs/` | 应用日志 |
| 系统凭据库 | 密码/私钥（操作系统级加密，不在上述目录） |

**备份建议**：迁移或重装前备份整个 `.nebula-ssh` 目录；凭据库随系统用户账户走，需在同系统同账户下才可读取。

## 15. 常见问题（FAQ）

**Q1：连接提示"指纹不匹配"怎么办？**
A：说明服务器指纹与上次记录不一致，可能服务器重装，也可能是中间人攻击。先与服务器管理员核实；确认无误后到「主机指纹管理」删除旧记录再重新连接。

**Q2：AI 助手无响应/请求失败？**
A：依次检查：① 设置里是否已选服务商并保存；② API Key 是否有效（点「测试连接」）；③ 使用 Ollama 时本机 `ollama serve` 是否在运行、模型是否已 pull；③ 公司网络是否需要配置代理。

**Q3：同步输入会不会误操作？**
A：会。开启期间所有按键广播到全部已连接终端。图标会闪烁提醒，批量操作完成后请立即关闭。

**Q4：SFTP 传输中断了要重头传吗？**
A：不需要。重新发起同一文件传输会自动从断点续传。

**Q5：数据库查询报"command not found"？**
A：远端服务器未安装 mysql/psql 客户端。NebulaX 经 SSH 在远端执行查询，需远端存在对应 CLI。

**Q6：巡检开启了但没看到通知？**
A：检查 ①「严重告警发通知」开关是否打开；② 是否有**已连接**的 SSH 会话（无会话无从采集）；③ Windows 通知是否被系统专注模式屏蔽。

**Q7：如何让 AI 完全离线？**
A：使用 Ollama 本地模型，所有推理在本机完成，数据不出内网。

**Q8：终端重连后之前的操作会丢吗？**
A：重连建立的是新会话，之前 shell 内的状态（如 cd、tmux 外的环境）会丢失；重要长任务建议在服务器上用 `tmux`/`screen` 保持。
